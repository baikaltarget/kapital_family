# Сайт центра здоровья «Капитал Фэмили», Ангарск

Next.js (App Router) + Tailwind. Статическая генерация, 30 страниц.
Разработка — Байкал Таргет.

---

## 1. Как выложить сайт (по шагам)

1. Зайти на github.com под аккаунтом `baikaltarget` → **New repository** → имя `kapital-femili` → Private → Create.
2. На странице репозитория: **Add file → Upload files** → перетащить **все папки и файлы из архива** (кроме `node_modules`, их в архиве нет) → внизу **Commit changes**.
3. Зайти на vercel.com → **Add New → Project** → выбрать репозиторий `kapital-femili` → **Deploy**. Настройки менять не нужно, Vercel сам поймёт Next.js.
4. Через 1–2 минуты сайт открывается по адресу вида `kapital-femili.vercel.app`. Проверить всё на нём.
5. Домен подключать **только после проверки**: Vercel → Settings → Domains.
6. После подключения домена поправить `content/site.json` → `site.url` (сейчас там адрес vercel) и сделать коммит — canonical и sitemap подтянутся сами.

## 2. Ключи (env-переменные)

Vercel → Settings → Environment Variables. Список — в файле `.env.example`.

| Переменная | Зачем |
|---|---|
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | заявки падают в Telegram |
| `NEXT_PUBLIC_YM_ID` | счётчик Яндекс.Метрики |
| `BITRIX_WEBHOOK_URL` | дублирование заявок в Битрикс24 |
| `AMO_BASE_URL`, `AMO_ACCESS_TOKEN` | дублирование в amoCRM |
| `RESEND_API_KEY`, `LEAD_EMAIL_TO`, `LEAD_EMAIL_FROM` | дублирование на почту |

Пока ключей нет, форма честно пишет «отправка не настроена» и показывает телефон, а заявка пишется в лог сервера (Vercel → Logs). Ничего не теряется, но лучше настроить Telegram сразу.

## 3. Где что править

Код трогать не нужно. Весь текст и цены — в одном файле.

| Что править | Где |
|---|---|
| Телефон, адрес, часы, реквизиты, лицензия | `content/site.json` → `org` |
| Цены и описания услуг | `content/site.json` → `services` |
| Прокол ушей | `content/site.json` → `prokol` |
| Специалисты | `content/site.json` → `team.members` |
| Отзывы | `content/site.json` → `reviews` |
| Статьи блога | `content/blog/*.md` |
| Фото | `public/img/` |
| Цвета и шрифты | `app/globals.css` (блок `:root`) |

Как править на GitHub: открыть файл → карандаш → изменить → **Commit changes**. Через минуту сайт пересоберётся сам.

### Красные рамки «нужны данные заказчика»

Пока данных нет, на страницах стоят красные рамки. Когда всё заполнено — выключить одним флагом:
`content/site.json` → `flags.showNeedsDataFrames: false`.

Отдельная услуга помечается `"needsData": true`, цена-черновик — `"priceDraft": true`.

### Добавить услугу

В `content/site.json` → `services` скопировать любой блок и поменять поля. Обязательные: `hub` (`massazh` или `basseyn`), `slug` (латиницей, это адрес страницы), `title`, `h1`, `metaTitle`, `metaDescription`, `lead`, `duration`, `priceText`.

Страница, пункт в меню раздела, перелинковка, прайс и sitemap появятся сами.

### Добавить статью

Новый файл в `content/blog/`, имя латиницей — это адрес. Начало файла:

```
---
title: "Заголовок статьи"
description: "Описание для поиска, 120–200 символов"
date: "2026-10-01"
---
```

Дальше обычный текст с подзаголовками `##`.

## 5. Что уже сделано по SEO

- На каждой странице один H1, title 45–73 символа, description 104–174 символа, canonical.
- JSON-LD: MedicalBusiness на всех страницах, Service + Offer с ценой на услугах, FAQPage, BreadcrumbList, BlogPosting, ItemList.
- Хлебные крошки, перелинковка между услугами и из статей.
- Sitemap и robots генерируются из контента.
- Кэш на `/img/` и `/fonts/` — в `vercel.json`.
- Шрифты локальные, с кириллицей, ничего не грузится со стороны.

## 6. Что нужно от заказчика

1. **Телефон и часы работы** — сейчас заглушка `+7 (000) 000-00-00`.
2. **Номер лицензии** на медицинскую деятельность.
3. **Цены-черновики**: массаж спины, руки, ноги, расслабляющий массаж, аквааэробика.
4. **Абонементы и курсы** — есть ли, сколько стоят.
5. **Специалисты** — имена, фото, специальности, стаж (4 карточки-заглушки).
6. **Отзывы** — 3–5 штук со скринами.
7. **Фото** — бассейн, массажный кабинет, занятия с людьми. Сейчас три фото помещений без людей.
8. **Соцсети и 2ГИС** — ссылки.
9. **Точка на карте** — координаты для карточки и JSON-LD.

## 7. Что сделать после публикации

1. Яндекс.Вебмастер: добавить сайт, подтвердить, отправить `sitemap.xml`.
2. Google Search Console — то же самое.
3. Яндекс.Метрику подключить через `NEXT_PUBLIC_YM_ID`, проверить события (цели `lead_*` на формах).
4. Яндекс.Бизнес и 2ГИС: адрес и телефон должны совпадать с сайтом **до символа**.
5. Переобход страниц в Вебмастере — относительными адресами (`/massazh/`), по 20–30 в сутки.
6. Через 1,5–2 месяца — первая выгрузка запросов из Вебмастера, по ней корректируем тексты.
